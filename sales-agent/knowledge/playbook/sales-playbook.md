# 営業Playbook

更新日：2026-09-15／管理：営業部 山本
※ デモ用の架空の内容です。

## 1. 誰に売るか

* **主なターゲット**：従業員300名以上で、拠点が複数ある会社。特に「本社と現場で承認が二重」「海外拠点の承認が見えない」会社
* **窓口になりやすい部署**：経理部、経営企画部、情報システム部
* **決裁者**：管理部門の役員、または業務改革の責任者。情報システム部はセキュリティ審査を担う

## 2. 営業の流れとステージ

ステージの定義と確度は `deal-stage-definitions.md` を正とする。

| ステージ | この段階のゴール | 次に進む条件 |
|---|---|---|
| S1 初回接触 | 課題があるかを確かめる | 課題ヒアリングの日程が決まる |
| S2 課題確認 | 承認業務のどこで、どれだけ困っているかを数字でつかむ | 決裁者と課題の認識が合う |
| S3 提案 | 課題に対する解決策と効果を示す | 先方が稟議を上げると言う |
| S4 稟議・条件調整 | 稟議を通す材料を揃える | 稟議承認 |
| S5 契約手続き | 契約書の締結 | 押印済み契約書の受領 |

## 3. 商談の型（初回〜提案）

1. **前提の確認**：前回までの合意事項、今日のゴールを最初に共有する
2. **現状を数字で聞く**：承認の件数、平均日数、止まりやすい工程
3. **影響を聞く**：止まると何が困るか（支払い遅延、機会損失、監査の指摘）
4. **理想の状態を聞く**：誰が、何を見られるようになればよいか
5. **次の行動を決める**：誰が、いつまでに、何をするか。必ずその場で決める

## 4. 質問集（よく効く質問）

### 現状をつかむ

* 「承認待ちが一番たまりやすいのは、どの部署・どの工程ですか？」
* 「1件の稟議が完了するまで、平均で何日かかっていますか？」
* 「拠点ごとに、承認のルールは違いますか？それを本社はどう把握していますか？」

### 影響をつかむ

* 「承認が止まったことで、支払いや発注が遅れた例はありますか？」
* 「監査で、承認の記録について指摘を受けたことはありますか？」

### 決め方をつかむ

* 「このような仕組みを入れるとき、どなたが、どの順で承認されますか？」
* 「情報システム部門の審査では、何を確認されますか？」

### 避ける質問

* 「ご予算はいくらですか？」から入る（課題を聞く前に予算を聞くと、比較検討の土俵に乗るだけになる）
* 「何かお困りごとはありますか？」（広すぎて答えにくい）

## 5. 業種別の切り口

| 業種 | よくある課題 | 響きやすい機能 |
|---|---|---|
| 商社 | 海外拠点の承認が見えない、多通貨 | 多言語・多通貨、拠点別ルール |
| 製造 | 工場と本社で承認が二重、購買の承認が多い | フロー設計、連携 |
| 製薬・金融 | 監査・規制対応 | 承認履歴 |
| 小売 | 店舗の発注承認が遅い | 滞留アラート |
| 建設 | 現場ごとに承認ルールが違う | 拠点別ルール |

## 6. 停滞したときの打ち手

* **活動が途切れた**：担当者の繁忙期を確認し、相手の負担が小さい次の一歩（15分の電話、資料1枚の確認）を提案する
* **稟議で止まった**：稟議資料の不足を聞き、こちらで作れる材料（効果試算、セキュリティ回答）を先に出す
* **決裁者に会えない**：窓口の方に「決裁者が気にしそうな点」を聞き、それに答える1枚を渡す
* **競合と比較中**：価格ではなく、拠点別ルールと滞留アラートの効果で比べてもらう。値引きは最後
